# mj_repo_saas 제품 기획서

상태: 초안 · 2026-11-14

## 제품 가설

개인 개발자와 소규모 팀은 프로젝트마다 프론트엔드, API, 앱, 문서를 다른 저장소에 둘 수 있다. 이슈나 커밋을 추적하기 전에, **이 프로젝트가 뭘 하는지, 어느 저장소를 열어야 하는지, 지금 무엇을 쓸 수 있는지** 빠르게 알고 싶다.

GitHub Projects의 업무 추적이나 DeepWiki의 개별 저장소 설명을 대체하지 않는다. 첫 차별점은 여러 저장소를 **사용자가 정한 프로젝트 단위**로 묶고, 구성 요소별 배포 근거를 나란히 보여주는 것이다. 프로젝트 하나가 저장소 하나일 수도 있다.

## 첫 사용자와 첫 화면

- 대상: 사이드 프로젝트가 여러 개인 개발자, 여러 저장소를 관리하는 소규모 팀.
- 카드 요약: 아이콘, 이름, 목적 한 줄, 짧은 설명, 프로젝트 상태, 대표 출시 근거 또는 확인 상태.
- 상세보기: 저장소별 역할, 호스팅 플랫폼, 사용 언어, Star·Watch·Fork 수, 최근 1년 주간 커밋 차트, 최신 정식 릴리스와 버전, 출처 링크, 마지막 확인 시각, 사용자 흐름 또는 구성 요소 흐름. 선택 항목은 확인된 데이터가 있을 때 표시한다. 펼침/접기와 차트의 주별 값은 키보드로 확인할 수 있게 한다.
- 목록: 이름·설명·저장소 검색, 상태 필터, 저장소·릴리스·배포 페이지로 이동.

## MVP 사용 흐름

1. 로그인 없이 공개 GitHub 또는 GitLab.com 저장소 URL을 붙여넣는다. 같은 저장소는 중복 제거한다. 비공개·삭제·일시 오류는 구분할 수 있는 범위까지만 설명한다.
2. 공개 메타데이터와 README를 바탕으로 카드 초안을 만든다. README가 없으면 확인된 이름·설명만 채우고 비어 있는 필드는 편집할 수 있게 한다.
3. 카드를 합치거나 분리하고 각 저장소 역할(웹, API, 문서 등)을 지정한다. 목적·설명·아이콘·흐름을 편집한다. 흐름 기본 템플릿 예: 사용자 → 웹 → API.
4. 대시보드를 브라우저에 저장하고 다시 연다. MVP에서는 브라우저 밖 공유나 기기간 동기화를 보장하지 않는다.
5. 사용자가 새로고침하면 저장소에서 수집한 정보를 갱신한다. 사용자 편집은 덮어쓰지 않는다. 조회 실패 시 마지막 확인값과 실패 시각을 표시한다.

## 데이터와 표시 기준

| 정보 | 표시 기준 |
|---|---|
| 목적·설명·흐름 | 사용자 입력 우선, 그다음 README 또는 저장소 설명. AI 요약을 추가하더라도 편집 가능한 초안으로만 표시. |
| 프로젝트 개발 상태 | 사용자 지정: 기획, 개발, 테스트, 운영, 보류 등. 커밋 빈도로 추정하지 않음. |
| 플랫폼·언어 | 저장소별로 호스팅 플랫폼을 표시한다. GitHub 언어 비중은 언어별 바이트 합계에서 계산한다. 대표 언어만 확인했으면 이름만 표시한다. [GitHub 언어 API](https://docs.github.com/en/rest/repos/repos#list-repository-languages) |
| Star·Watch·Fork 수 | GitHub 저장소 응답의 `stargazers_count`, `subscribers_count`, `forks_count`를 사용한다. 응답에 있는 0은 그대로 표시하고, 누락된 항목은 생략한다. `watchers_count`는 Star 수를 나타내는 레거시 필드다. [GitHub Watch API](https://docs.github.com/en/rest/activity/watching) |
| 커밋 활동 | GitHub 기본 브랜치 기준 최근 1년의 주별 커밋 수를 막대 차트로 표시한다. 이 통계는 머지 커밋을 제외한다. 주 시작일과 커밋 수를 확인할 수 있게 하고 원본 저장소로 연결한다. 통계 준비 중(`202`)이면 잠시 뒤 재조회한다. 본문 없음(`204`)이나 미조회 상태에서는 새 차트를 표시하지 않는다. 갱신 실패 시 마지막 확인값이 있으면 확인 시각과 함께 표시한다. [GitHub 통계 API](https://docs.github.com/en/rest/metrics/statistics#get-the-last-year-of-commit-activity) |
| 최신 정식 릴리스 | GitHub Releases의 공개 정식 릴리스만 사용. 프리릴리스는 별도 표시. 태그 단독은 출시 증거가 아님. |
| 배포 근거 | 사용자가 등록한 배포·스토어·다운로드·문서 링크를 유형별 표시. URL 등록만으로 동작이나 서비스 배포를 자동 검증했다고 말하지 않음. |
| 출시 여부·현재 버전 | 구성 요소별로 표시. 공개 문서는 앱 출시가 아님. 릴리스 조회는 성공했지만 근거가 없으면 ‘출시 확인 안 됨’. 조회 실패는 ‘조회 실패’로 별도 표시. |

최소 모델: 프로젝트, 저장소(호스팅 플랫폼·원본 URL), 프로젝트–저장소 연결(역할·순서), 흐름 단계, 버전/배포 근거(출처·확인 시각). 수집한 언어, 지표, 커밋 활동은 저장소별 선택 데이터로 두고 출처와 확인 시각을 저장한다. 사용자 편집과 자동 수집 데이터를 분리한다.

## 다른 저장소 서비스 검토

| 서비스 | 표시 가능한 데이터와 연동 조건 |
|---|---|
| GitLab.com | 프로젝트 API에서 Star·Fork 수와 언어 비중을 조회할 수 있다. 기본 브랜치의 커밋 목록을 기간으로 제한해 주별로 집계할 수 있다. 프로젝트 응답에 공개 Watch 수가 없어 해당 항목은 생략한다. [프로젝트 API](https://docs.gitlab.com/api/projects/) · [커밋 API](https://docs.gitlab.com/api/commits/) |
| Bitbucket Cloud | 저장소의 `language` 값과 커밋 목록을 사용할 수 있다. Watch·Fork는 페이지로 나뉜 별도 목록에서 조회 가능한 범위의 수를 확인한다. 언어 비중과 Star 수는 생략하는 방향으로 검토한다. [저장소 API](https://developer.atlassian.com/cloud/bitbucket/rest/api-group-repositories/) · [커밋 API](https://developer.atlassian.com/cloud/bitbucket/rest/api-group-commits/) |
| Codeberg | Forgejo 기반이며 Watch·Star·Fork와 저장소 활동을 제공한다. 연동 전 Codeberg 인스턴스에서 익명 API 조회 범위와 언어·커밋 응답을 확인한다. [Codeberg 저장소 안내](https://docs.codeberg.org/getting-started/first-repository/) · [Forgejo API 안내](https://forgejo.org/docs/latest/user/api/usage/) |

GitHub와 GitLab.com 공개 저장소를 지원한다. GitLab.com은 기본 브랜치의 커밋 시각을 기준으로 일요일 UTC에 시작하는 52주(이번 주 포함)를 집계하고 머지 커밋을 제외한다. 기간 내 기록을 전부 조회하지 못하면 차트를 생략한다.

## 구현 방향과 안전 기준

- 정적 프로젝트 카드·검색·상세보기 UI를 재사용하고, 공개 저장소 조회와 자동 갱신값을 분리한다. GitHub Releases/README/메타데이터 조회에 [GitHub REST API](https://docs.github.com/en/rest)를 사용한다.
- 입력은 GitHub와 GitLab.com의 저장소 URL을 허용하며, 파싱한 저장소 경로로 해당 서비스의 정해진 API에 요청한다. 임의 사이트를 대신 가져오지 않는다. README는 신뢰하지 않는 입력으로 취급하고, 렌더링 시 실행 가능한 HTML을 제거한다.
- 외부 요청은 캐시·요청 제한을 두고 한도 도달 시 안내한다. 서버 토큰이 필요하면 브라우저에 노출하지 않는다.
- 초기에는 AI 없이도 쓸 수 있게 한다. 향후 AI를 사용한다면 README의 지시문을 따르지 않고 요약을 위한 데이터로만 사용한다. 비공개 콘텐츠를 외부 AI에 보내는 기능은 별도 동의 없이는 제공하지 않는다.
- 비공개 연동이 필요해지면 [GitHub App](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party)으로 사용자가 선택한 저장소에 필요한 읽기 권한만 요청한다. 비공개 카드의 공개 공유는 기본적으로 막고, 연결 해제 시 동기화 중단 및 데이터 삭제 정책을 마련한다.

## 초기 합격 기준

- 공개 URL 세 개를 넣고 두 개를 한 카드로 묶어, **3분 내** 목적·역할·최신 릴리스와 근거 링크를 확인할 수 있다.
- 정식 릴리스만 있음, 프리릴리스만 있음, 태그만 있음, README 없음, 요청 한도 도달 케이스가 섞여도 잘못된 출시 표기가 없다.
- Watch 0과 Watch 미제공을 구분하고, 커밋 통계 준비 중 또는 조회 실패 시 커밋 0건으로 표시되지 않는다. 같은 프로젝트에 묶인 저장소도 각자 확인된 언어와 지표를 표시한다.
- 브라우저를 새로고침해도 편집 내용이 남고 저장소 정보를 다시 가져와도 설명이 유지된다.
- 초기 사용자 5명에게 자신의 프로젝트를 만들게 한다. 5명 중 3명 이상이 도움 없이 첫 카드를 완성하고, 2명 이상이 7일 이내 다시 열거나 갱신하는지를 방향 판단용으로 본다. 작은 실험 결과를 일반화하지 않는다.

## 순서와 사업 가설

1. 공개 저장소 가져오기, 편집, 그룹화와 출시 근거 표시.
2. 초기 사용자 관찰. 재방문이 적고 공유 수요가 높다면 포트폴리오 생성기로, 재방문·갱신 수요가 있다면 관리 도구로 좁힌다.
3. 반복 사용이 확인되면 비공개 저장소 연동과 자동 갱신을 유료 후보로 검증한다. 가격은 아직 정하지 않는다.

첫 버전 제외: Bitbucket/Codeberg, 코드 전체의 AI 분석, 팀 권한 관리, 배포 자동화, 결제, 공개 포트폴리오 호스팅.
